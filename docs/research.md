## 二 用户需求验证（B-2）

### 2.1 当前状态

**访谈未完成。** 0 位真实用户被访谈过。本节用**任务走查**作为**有限的替代**证据，明确标注为"团队观察"而非"外部事实"。

### 2.2 目标用户描述（产品假设，未证实）

假设的目标用户画像：

- **谁**：需要办理一项政策类申请的个人，本地租房补贴 / 人才补贴 / 学历相关补助为最贴近的场景。
- **场景**：已找到目标政策文件（PDF 或政务网页复制文本），但不确定"我是否符合"、"要交什么材料"、"什么时候截止"。
- **痛点假设**：
  - 政策条款结构复杂，条件之间有"且 / 或 / 除外"逻辑，易漏读。
  - 现有大模型问答会给出**看起来合理但引用不准**的答案，用户难以核验。
  - 材料清单散落在多条款中，用户需要自行拼接。

**上述均是产品假设**，需要 3 位以上真实潜在用户的访谈或任务走查数据来证实或推翻。

### 2.3 任务走查（团队观察，2026年9月13日）

在 `examples/policy.txt`（内置示例政策）上执行 `proofpath demo`，模拟"一位硕士毕业 28 岁、社保 8 个月、想申请租房补贴"的用户。观察结果（引 `docs/baseline.md` §2.3）：

| 观察项 | 结果 | 说明 |
|---|---|---|
| 条件拆分 | 6 条 | 学历、年龄、社保、住房、租赁备案、申请时限 |
| 逐条判定 | MET × 3 · NEEDS_INPUT × 1 · UNKNOWN × 2（降级后） | 用户能明确看到哪些条件已满足、哪些还差信息 |
| 材料清单 | 7 项 | 每项对应原文条款可回溯 |
| 缺失信息提示 | "住房租赁合同网签备案的具体日期" | 系统主动要求补充，未擅自推断 |
| 引用拦截 | 2 处 | 一处编造（覆盖率 11%）、一处过短（"合同"两字），均降级为"原文未明确" |

**这是团队自建证据，不能替代真实用户访谈。** 走查证明的是"系统在预设输入下能给出期望的输出结构"，并未证明"目标用户实际会用、能用、愿意用"。

### 2.4 访谈计划（未执行）

一旦项目负责人给出招募渠道或名单，按以下计划推进：

- **样本数**：3 位潜在申请人（不同学历 / 年龄 / 城市，避免同质化）。
- **时长**：每人 20–30 分钟。
- **形式**：
  1. 前 5 分钟：请他们描述最近一次"看政策文件申请补贴 / 补助"的过程。
  2. 中 15 分钟：让他们独立使用 `proofpath demo` + 一份**脱敏真实政策**，记录卡点。
  3. 后 5–10 分钟：结构化追问（对结论的信任度、是否会核验引用、缺哪些信息）。
- **交付**：`docs/interviews/<日期>-<代号>.md`，含原始记录 + 团队观察 + 需求条目更新。

访谈完成前，本节所有"需求条目"仍标记为**未证实假设**。

### 2.5 需求条目候选（假设，需访谈验证）

| 编号 | 需求条目 | 优先级假设 | 待证事项 |
|---|---|---|---|
| N-1 | 一次上传一份政策文件，拿到"我是否符合"的初步判断 | 必须 | 用户是否会真的上传，或直接复制原文 |

## 三 竞品与替代方案（B-3）

### 3.1 当前状态

**未指定竞品名单。** 项目负责人未指出具体的对标产品。本节按 0 号文件 §三 的默认逻辑，围绕**用户当前会怎么办**做三类对比走查。

### 3.2 三类替代方案（走查，非评分）

| 类别 | 代表方式 | 用户体验 | 与 ProofPath 的差别 |
|---|---|---|---|
| 手工办理 | 打开政策 PDF / 政务网页，自己逐条读 | 完全免费；耗时且易漏读；条件复合时易误判 | ProofPath 把条件结构化并附引用 |
| 通用大模型问答 | 复制政策原文到通用聊天窗口提问 | 快；输出流畅；**引用无法核验**，出现真伪拼接时无法察觉 | ProofPath 用 `verifier.py` 逐字核验，编造引用会被降级 |
| 现有政策问答 / 智能咨询 | 政务平台或城市 App 的"智能问答" | 覆盖面广但结论粒度粗；难以追溯到原文条款 | ProofPath 强制"每条结论 → 每条引用 → 原文页码" |

**这只是分类走查。** 具体产品的对比需要项目负责人指定名单后，逐个跑一次相同的问题，记录：结论 / 是否附来源 / 是否能核验来源 / 是否会拦截错误引用。

### 3.3 ProofPath 目前可以宣称的差异（有实测证据）

以下三点在 2026年9月13日的运行基线中已验证（引 `docs/baseline.md` §2.3）：

1. **一条结论里任何一个引用无法定位，整条降级。** 复合结论（"1500元 且 可追补3个月"）里的编造部分会被拦下。
2. **过短的引用（"合同"两字）不算证据。** 结论被降级为"原文未明确"，而非表面显示"已核验"。
3. **敏感操作前系统停止。** `plan` 命令在 `upload / submit` 处停止，退出码 3，不留半成品。

### 3.4 ProofPath 目前不能宣称的差异

以下声明**没有实测证据**，本轮不进入演示文案：

- "准确率高于 XX%"——没有对照评测。
- "比手工节省 XX 分钟"——没有对照任务。
- "获奖概率"——不在本项目应发布的信息范围（0 号文件 §3.4）。
- "实时调用"——`proofpath check` 从未跑通过（引 `docs/baseline.md` §四.1）。
- "跨平台可用"——仅在 Windows + Python 3.13 验证。

项目负责人指定竞品名单后，本节按以下方式更新：
