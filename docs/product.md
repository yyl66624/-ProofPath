## 一 一句话定位

**ProofPath 帮助用户把一份政策文件转成带原文引用的初步资格判断和材料清单，并在证据不足时主动降级而非编造。**

首版**不做**最终资格认定、真实付款、无人值守申请提交。

## 二 核心用户故事

> 作为申请人，我希望上传一份政策通知并补充自己的情况，看到逐项条件的判定、材料清单和原文出处；当我缺少必要信息时，系统清楚告诉我要补什么，而不是替我猜。

**成功判据**：用户在 3 分钟内能从"我不确定"走到"我知道下一步做什么"，且每一条结论都可以点到原文对应位置。

## 二·五 信任边界

**信任边界 = `src/proofpath/verifier.py` 的 `verify_report`**。这是本项目所有其他决策的基石，也是 §三 M-04 / M-05 / M-06 三条必须项的共同来源、§四 演示第三件事（"系统遇到错误时如何处理"）的实现机制。

- **模型输出默认不被信任**：无论用哪个模型（当前 Claude、P06 后 DeepSeek，见 [`docs/decisions.md`](decisions.md) D-012 与 [`docs/model-verification.md`](model-verification.md)），`reasoner.py` 返回的每一条引用初始状态都是 `NOT_FOUND` / `coverage=0.0`。
- **每一条 MET / UNMET 结论**都必须由 `verify_report` 重新在原文里逐字定位；任一条引用无法定位（`NOT_FOUND` / `TOO_SHORT` / `BAD_PAGE`）就把**整条结论**降级为 `UNKNOWN`，rationale 追加"证据核验未通过"。
- 换模型、加缓存、上前端、接浏览器执行——**都不允许放松这条规则**。任何"因为模型很强所以可以少验证"的改动都属范围外，必须走 0 号文件 §十五 变更记录。
- 引 `docs/decisions.md` D-012 §四 与 [五人分工清单](../00-项目文档/01-五人分工与任务清单.md) C-12："`verify_report` 仍是唯一信任边界，不因换模型放松"。

这是 ProofPath 对用户唯一的硬承诺：**你看到的每一条'已核验'结论，一定是逐字对得上原文的**。

## 三 首版功能边界（对齐 0 号文件 §3.3）

### 3.1 必须项（First Release Must-Have）

| ID | 功能 | 验收要点 |
|---|---|---|
| M-01 | 上传 / 加载支持格式：`.txt`、`.md`、含文本层的 `.pdf` | 三种成功、格式不支持、无可抽取文本均有明确反馈（T01 / T06） |
| M-02 | 输入用户问题 + 可选个人资料键值对 | 缺项时系统显式提示"我需要你告诉我 X"，不擅自推断（T02） |
| M-03 | 条件逐条判定，四种状态可区分：`MET / UNMET / NEEDS_INPUT / UNKNOWN` | 输出结构对应 `models.ConditionStatus`，UNMET 与 UNKNOWN 不合并（T01 / T02） |
| M-04 | 每条 MET / UNMET 结论必须附至少一条引用（页码 + 逐字片段）| 无引用的 MET / UNMET 强制降级为 UNKNOWN（`verifier.py` 现有行为） |
| M-05 | 引用被 verifier 逐字核验，失败者标注状态：`NOT_FOUND / TOO_SHORT / BAD_PAGE` | 五类状态在渲染层可区分（`render.py` 现有映射，T03） |
| M-06 | 任意一条引用无法定位 → 整条结论降级 | 拦截"真伪拼接"复合结论；`verifier.verify_verdict` 现有 AND 语义（T04 部分） |
| M-07 | 材料清单：每项能追溯到某条条款或某条用户输入 | 演示时可指到出处（`render_report` §材料清单，T01） |
| M-08 | 一份**完整正常流程**（`demo` 命令跑通）能被任意干净环境复现 | `docs/baseline.md` 已固化预期输出（T01） |
| M-09 | 一份**完整异常流程**（编造引用 + 过短引用）能被拦下 | `demo` 已嵌入两处缺陷；两处均降级（`docs/baseline.md` §2.3） |
| M-10 | 敏感操作（提交 / 上传 / 支付 / 删除）在未确认前不执行 | `plan` 遇到 `SENSITIVE` 停止、退出码 3（T12 部分） |
| M-11 | 审计链：每步关键操作可写入 SHA-256 哈希链；`audit` 命令能报出断裂位置 | `audit.py` 现有实现；日志无 delete / update 接口 |
| M-12 | 每一次演示结束必须显式提示"本结果不是最终资格认定" | `render_report` 已在报告末尾追加提示 |

### 3.2 可选项（时间允许才做，不进入 Demo 必备）

| ID | 功能 | 触发条件 |
|---|---|---|
| E-01 | 扫描件 OCR / DOCX / PPTX 解析（docling 分支） | 出现真实扫描件或 Office 格式素材时启用；单独验证准确率与依赖体积 |
| E-02 | 受控网页辅助填表（browser-use 分支） | 赛题明确要求 Agent 操作能力；同时要削减其他扩展项 |
| E-03 | HTTP 接口 + 简易前端 | 由 D / C 决定；不影响 CLI 演示的可复现性 |

### 3.3 延后（不计入首版承诺）

- 实时语音输入 / 输出
- 多网站自动办理、跨站点导航
- 长期监控政策更新与订阅
- 真实付款、真实提交
- 多用户账户与访问隔离（若不做，T10 明确标"不涉及"）

### 3.4 不在首版（禁止对外宣称）

- 最终资格认定
- 无人值守的申请提交
- "比手工节省 XX 分钟" / "准确率 XX%" 类的量化承诺（无对照评测证据）
- "获奖概率" / "行业最佳"（0 号文件 §3.4 明确禁止）

## 四 演示时要让观众看到的三件事（对齐 0 号文件 §3.4）

1. **用户少做了什么**：条件不用自己拆、材料不用自己拼、引用不用自己找。
2. **结论如何追溯到原文**：任意一条判定都能点到页码 + 逐字片段。
3. **系统遇到错误时如何处理**：编造引用被拦、过短引用被拦、敏感操作被拦、结论强制降级。

**不能演示的**：真实模型调用（未跑通）、真实浏览器执行（未接线）、扫描件 OCR（未安装 docling）。
