## 三、T01–T12 逐场景判定

| 编号 | 场景 | 判定 | 依据 |
|---|---|---|---|
| T01 | 支持文件 + 完整信息 | ✅ CLI 离线通过 | parse→retrieve→reason→verify→render 使用脚本化推理器完成；未验证 Web 服务或真实模型 |
| T02 | 缺少用户信息 | ✅ 通过 | NEEDS_INPUT 状态正确传播，渲染输出含"待补充"、"需要你提供" |
| T03 | 编造引用 | ✅ 通过 | 纯虚构(NOT_FOUND)、拼接虚构(非VERIFIED)、复合引用(一真一假整条降级) 均验证 |
| T04 | 引用真实但不支持结论 | ⚠️ 已知差距 | 验证器仅检查字符串可定位性，不检查逻辑支撑关系。测试存在并记录此差距，标记为 **模型质量评估项** |
| T05 | 例外条款/多文件冲突 | ⚠️ 部分覆盖 | 当前为单文件系统，多文件冲突不适用。例外条款依赖模型能力，测试覆盖了 UNKNOWN 状态传播 |
| T06 | 扫描件/空文件/损坏/不支持 | ⚠️ 部分覆盖 | 空文件、损坏 PDF、无文字层 PDF 与不支持格式的错误路径已测；真实扫描件 OCR 路径未测 |
| T07 | 超时/无权限/额度不足/异常输出 | ⚠️ 部分覆盖 | 429、连接失败、拒答及空响应的错误路径已测；超时后输入保留与截断 JSON 尚未完成 |
| T08 | 文档含提示注入 | ⚠️ 部分覆盖 | 6 种注入文本可被解析，伪造引用被核验拒绝；**未测试模型读取后是否服从注入** |
| T09 | 重复点击/刷新/取消 | 🔄 延迟 | 无前端；ActionGate 有阻断测试，但不具备幂等去重 |
| T10 | 多用户访问隔离 | 🔄 延迟 | 系统不含多用户能力，无需验证。如引入需补充 |
| T11 | 日志不暴露密钥 | ⚠️ 部分覆盖 | 结构化敏感字段写入审计日志前脱敏，并验证磁盘文件与哈希链；自由文本、所有错误路径及仓库级扫描不能由此保证 |
| T12 | 填表确认/拒绝/网页变化 | ⚠️ 部分覆盖 | ActionGate deny-by-default、SENSITIVE 操作需确认；只有 DryRunExecutor，未验证真实网页变化或提交 |

## 四、误判分类法（依据 0号文件 9.4）

以下分类定义来自测试计划（docs/test-plan.md），此处记录当前验证器的拦截能力：

| 编号 | 误判类型 | 当前拦截 | 测试覆盖 |
|---|---|---|---|
| M1 | 虚构引用（凭空捏造） | ✅ NOT_FOUND 降级 | test_completely_fabricated_quote |
| M2 | 错位引用（正确文字错误页码） | ✅ NOT_FOUND 降级 | test_real_quote_wrong_page_rejected |
| M3 | 截断引用（过短无证据力） | ✅ TOO_SHORT 降级 | test_too_short_citation (原有) |
| M4 | 断章取义（真引用不支持结论） | ❌ 仅字符串匹配 | test_real_quote_verifies_even_if_logic_wrong（标记差距） |
| M5 | 不相关引用（文不对题） | ❌ 不检查 | 模型质量评估范畴 |
| M6 | 漏判条件（遗漏政策条件） | ❌ 依赖模型 | 模型质量评估范畴 |
| M7 | 过度推断（NEEDS_INPUT 应判 MET） | 🔶 部分（降级逻辑） | NEEDS_INPUT 传播已测试 |
| M8 | 过度保守（全判 UNKNOWN） | ❌ 依赖模型 | 模型质量评估范畴 |
| M9 | 忽视例外条款 | ❌ 依赖模型 | T05 标记为已知差距 |
| M10 | 信息补全遗漏 | ❌ 依赖模型 | missing_info 渲染已测试 |
| M11 | 幻觉条件（政策中不存在的条件） | ❌ 依赖模型 | 模型质量评估范畴 |
| M12 | 提示注入服从 | ❓ 未验证模型行为 | 仅验证文本解析与伪造引用拒绝；6 种注入未进入真实模型调用 |

**核心结论**：确定性测试支持 M1/M2/M3 的引用定位拦截；M4–M12 的模型行为和语义风险需要独立评估，不能以代码覆盖率推断。

## 五、模型质量评估

### 5.1 当前状态

- **真实模型链路**：主线 `docs/model-verification.md` 记录了同一份样例的 3 次 DeepSeek 脚本级真实调用；这不是产品 `check` 命令、Web 服务或模型质量评估。`check` 仍绑定 Anthropic SDK（P06 未完成）。本次复核不使用 API 密钥。
- **离线评估**：demo 路径（ScriptedReasoner）的预置报告覆盖正确引用、虚构引用、过短引用，验证了核验管线工作正常。
- **正式质量评估样本数**：0；上述 3 次接线验证不构成独立案例集，不能给出正确率。

### 5.2 模型评估建议指标（依据 0号文件 9.4）

当真实 API 密钥可用后，应建立以下指标：

| 指标 | 定义 | 建议样本数 |
|---|---|---|
| 条件判断正确率 | 人工标注的条件状态 vs 模型输出 | ≥ 20 案例 |
| 引用可定位率 | 引用通过 verify_citation 的比例 | 自动计算 |
| 证据支撑正确率 | 人工判断引用是否支持结论（T04） | ≥ 20 案例 |
| 拒答处理 | 应拒答案例模型是否正确使用 UNKNOWN/NEEDS_INPUT | ≥ 5 案例 |

### 5.3 已知差距

T04（引用-结论语义匹配）是当前最大的质量盲区。验证器按设计只核查"原文中是否存在该引用"，不核查"该引用是否支持该结论"。这是有意的架构选择（见 docs/decisions.md），但意味着：

> 一个模型如果用真实引用支撑错误结论，当前系统不会拦截。

修复路径：引入二次模型判断或基于规则的语义相关性检查，属 P06 或后续版本范畴。

## 七、发布评估意见

### 7.1 判定：**模块级复核通过不等于 Demo 发布通过** ⚠️

本版本可继续离线 CLI 预览；是否进入正式 Demo 展示阶段，仍需满足 0 号文件的目标环境演示门槛。当前没有 Web 前端、真实表单执行器或已接入 DeepSeek 的产品 `check`。

**已验证范围**：CLI 离线样例、引用字符串定位及降级、ActionGate 阻断、结构化审计字段脱敏和自动化回归。T08 模型抗注入、T12 真实网页执行与 T04 语义支撑均未通过验证。

**阻断条件（若声明真实模型服务）**：
1. ❌ 产品真实模型链路未验证 → 若主打真实模型服务，**阻断发布**（主线已有 3 次脚本级调用，不等于产品端到端）
2. ❌ 正式模型质量评估样本数 = 0 → 不能声称判断可靠性或抗提示注入能力
3. ❌ 目标环境连续三次核心演示及一次异常恢复尚未记录 → 正式 Demo 发布判定待定

**建议**：
- 可展示明确标注"离线预置样例"的技术预览，但不应宣称已满足正式 Demo 验收。
- 若 Demo 声称接入真实模型并给出可靠判断，需先完成 P06（DeepSeek 迁移）、至少 20 案例的模型评估及目标环境复验。
