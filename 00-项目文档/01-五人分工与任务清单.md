## 一 使用说明

本文把 0 号文件的三套编号直接用起来，避免另造一套：

- **P00–P12**：工作包（0 号文件第十一章），每个工作包只有一位最终负责人。
- **G0–G5**：阶段（0 号文件第十章），用于排期与"离开阶段的条件"。
- **T01–T12**：必测场景（0 号文件 9.3），用于测试分工与验收。

每条任务的"通过标准"按 0 号文件 9.1 写成可检验的句子：**成果已纳入目标版本、相关检查通过、限制已记录、他人能依据说明复现**。写完代码或提交 PR 都不算完成。

三个待填项未确定前，按代号和相对排期推进，不得自行编造：**成员名单、赛题与评分标准、截止时间**。

## 二 事实基线（2026年9月13日实测，可直接作为 P01 起点）

以下为本次实际执行结果，不是引述 README：

| 项目 | 实测结果 |
|---|---|
| 测试 | 132 项全部通过（`pytest`），覆盖率 90% |
| 分模块覆盖率 | verifier 98%、actions 100%、models 100%、retrieval 100%、text 100%、render 96%、reasoner 84%、cli 83%、parsers 59% |
| 依赖前提 | 裸 Python 环境为 124 通过 / 8 失败，8 项全因缺 `anthropic`、`pypdf`；安装声明依赖后全绿 |
| 离线链路 | `demo` 跑通，两处埋设缺陷均被拦下（编造引用覆盖率 11% → 未找到；两字引用"合同" → 引用过短），对应结论降级为"原文未明确" |
| 动作闸门 | `plan` 在 `upload`（SENSITIVE）处停止，退出码 3，符合 README |
| 可选组件 | docling（OCR/多格式）、browser-use（表单执行）均未安装；`DryRunExecutor` 是唯一执行器 |
| 仓库形态 | 本地目录**不是 git 仓库**，是远端 `main`（`c3f723a`）的压缩快照；逐文件比对内容一致（仅 Windows 换行符差异） |
| 现有资产 | 约 850 行源码、5 个测试文件、纯命令行界面 |

由此得到四条对分工有直接影响的结论：

1. **核心证据链已可用**，G3 的开发重心不在重写核验逻辑，而在补产品化外壳。
2. **前端、HTTP 接口、任务状态三者完全不存在**，P04–P07 是从零开始的工作量主体。
3. **verifier 只检查"引用能否定位"，不检查"引用是否支撑结论"**（0 号文件 T04、第二章均已点明），这是当前最大的技术缺口。
4. **真实模型链路从未验证过**：`check` 没有跑通过，模型名与回退参数只是配置值。

| D-5 | 证据面板：点引用跳转原文片段并高亮定位 | 定位成功与定位失败都有明确反馈；**核验未通过的引用绝不显示为已验证** |
| D-6 | 判断状态的表达 | 文字与视觉提示同时表达，不只依赖红绿颜色 |
| D-7 | 加载与重复操作 | 加载超时不伪造完成百分比，只展示真实状态；重复点击不创建重复任务 |
| D-8 | 可访问性与布局鲁棒性 | 键盘可完成核心操作；长文件名、长引用、空结果均不破版 |
| D-9 | 界面自检清单 | 主要屏幕无遮挡、文本与按钮可读、成功/失败/取消/返回路径完整 |
| D-10 | 手机适配（按赛事展示环境决定，待 B 确认） | 若列为必须项，则给出实际屏幕尺寸下的检查记录 |

### 8.3 依赖与禁区

依赖 C 的契约与样例接口；依赖 B 的 P03 确定流程范围。禁区：前端不自行决定资格状态、不实现一套本地"通过/不通过"逻辑；不持有服务端密钥；不得用颜色或动效暗示一个未被核验的结论。

## 十二 协作机制

| 事项 | 约定 |
|---|---|
| 分支命名 | 包含工作包、阶段或场景编号：`feat/P06-api-layer`、`fix/T04-support-check`、`docs/P03-acceptance-set`、`chore/G0-repo-governance` |
| PR | 一个 PR 对应一个可审核成果；四要素（用户可见变化、关联任务、测试结果、限制）缺一不可 |
| 合并 | 不以"我本机能跑"为依据；共享文件与核验逻辑改动需指定审查人通过 |
| 冲突 | 由改动负责人结合 A 处理，保留他人无关修改，不用整体覆盖解决 |
| 接口变更 | 先改 `docs/api-contract.md`，再通知 C、D、E，最后改代码 |
| 技术栈与依赖 | 后端固定为 Python 3.12 + FastAPI + Uvicorn；新增依赖写进 `pyproject.toml` 并由 A 审核（D-009） |
| 接口冻结 | 默认 2026年9月16日 24:00 冻结；冻结后任何字段或语义变化都记录一条 D-xxx，并在 24 小时内通知 C、D、E（D-011） |
| 模型与凭证 | 模型统一用 DeepSeek（默认 `deepseek-flash`）；密钥只出现在环境变量或密码管理器，分发只走私聊或共享密码库，禁止进群聊与仓库（D-012、D-013） |
| 每日同步 | 只报三件事：已完成成果及链接、当前阻塞、下一步交付。建议每天一次 |
| 任务状态 | 待澄清 / 可开始 / 进行中 / 待审查 / 待验收 / 已完成 / 阻塞 |
| 演示资料 | 实时调用、缓存结果、离线预设、受控表单必须清楚区分 |

## 十三 风险与削减顺序

| 风险 | 提前检查 | 处理 |
|---|---|---|
| 赛题不匹配或复用代码不符合规则 | B 读官方规则并留来源 | 调整场景或复用范围，保留贡献说明 |
| 功能堆积挤压交付 | A 对里程碑 | 先砍扩展功能，保留联调与验收 |
| 模型幻觉或遗漏条件 | E 跑保留验收集 | 显示不确定性、补全信息、缩小支持范围 |
| 文档解析效果不足 | C 验目标格式与代表样例 | 明确支持格式，必要时再上 OCR |
| 外部网站变化导致失败 | C、D 在目标环境验证 | 首版只用受控页面并标注演示属性 |
| 模型账号、费用或网络不可用 | A 核对服务与预算 | 设超时与重试上限，准备标记清楚的离线演示 |
| 多人接口不一致 | A 组织的契约评审 | 单一接口文档 + 指定共享模块负责人 |
| 环境无法复现 | A 的干净环境重建 | 固定依赖、记录环境、保留上一稳定版本 |

延期时的削减顺序（0 号文件第十章）：实时语音 → 多格式支持 → 多场景 → 自动填表。若赛事把 Agent 操作能力列为必需，重新调整顺序并留下决策记录。
