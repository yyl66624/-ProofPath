项目范围、成员分工、开发协作、测试验收与 Demo 交付方案统一见此文档。

把政策文件变成**有原文证据、可核验**的办事结论。

上传政策 PDF 或通知，直接问「我符合条件吗、要准备什么」。每一条结论都必须附上
能在原文中逐字定位的引用；定位不到的结论会被系统强制降级，而不是照原样呈现给用户。

## 核心设计：模型说的话不算数

模型负责读取政策片段并提出判断，但它的输出不被信任。`verifier.py` 会把每一条引用
拿回原文逐字比对，任何无法定位的引用都会让该条结论从「满足／不满足」降级为
「原文未明确」。

这一层是纯离线、确定性的，不依赖模型表现是否稳定 —— 也就是说，系统的可信度不取决于
模型这一次有没有说谎。

三条具体规则：

- **逐字比对**，但对 PDF 抽取产生的空格、全角半角、零宽字符做归一化，避免误判。
- **引用过短不算证据**。「合同」两个字能匹配几乎任何政策页，因此不足为证。
- **一条结论里只要有一个引用无法定位，整条降级**。这是为了拦住复合结论：
  「硕士1500元，**且**首次申请可追补3个月」把一句真话和一句编造拼在一起，
  只要求「至少一个引用为真」的宽松规则会让它通过，用户就会以为自己能拿到
  政策从未承诺的追补款。

## 快速开始

```bash
uv venv --python 3.12
uv pip install -e ".[dev]"

# 离线跑通完整链路，不需要任何凭证
proofpath demo
```

`demo` 使用内置示例政策和一份**故意埋了两处问题**的预设回答：一处引用是编造的，
一处引用短到不足为证。输出会显示这两条被拦下来的过程 —— 演示的重点不是模型能答，
而是系统能在模型出错时兜住。

## 命令

| 命令 | 说明 | 需要凭证 |
|---|---|:--:|
| `proofpath demo` | 离线跑通完整链路（含证据核验拦截） | 否 |
| `proofpath parse <文件>` | 解析文档并按页预览 | 否 |
| `proofpath search <文件> -q <问题>` | 只做检索，看命中了哪些片段 | 否 |
| `proofpath plan <网址>` | 展示表单执行计划的风险分级（演练，不执行） | 否 |
| `proofpath audit <日志>` | 校验审计链完整性 | 否 |
| `proofpath doctor` | 检查可选组件安装情况 | 否 |
| `proofpath check <文件> -q <问题>` | 真实判定资格 | **是** |

真实调用需要凭证：

```bash
export ANTHROPIC_API_KEY=sk-ant-...   # 或安装 ant CLI 后执行 ant auth login

proofpath check examples/policy.txt \
  -q "我硕士毕业28岁，社保交了8个月，能申请多少？" \
  -p 学历=硕士 -p 年龄=28 \
  --audit run.jsonl
```

## 执行安全

表单自动填写按风险分三级，分级逻辑在 `actions.py`，与浏览器实现解耦，
因此可以脱离浏览器测试：

- `READ_ONLY` — 打开页面、读取、截图
- `LOCAL_WRITE` — 填写字段，可撤销、未提交
- `SENSITIVE` — 提交、上传、支付、删除

两条硬规则：**不认识的动作一律按 SENSITIVE 处理**（宁可多问一次，也不要误提交一份
政府申请）；**填写动作若指向支付类字段，会自动升级为 SENSITIVE**。所有 `SENSITIVE`
操作默认拒绝，必须显式确认才会执行；计划在第一个被拦下的动作处停止，
不会留下「看起来跑完了」的半成品。

`plan` 命令退出码 3 表示「已在敏感操作前停止」，不是失败。

## 审计链

每一步关键操作（文档解析、结论降级、字段填写、提交确认）都会写入哈希链。
任何一条记录被事后修改，`proofpath audit` 都会指出断裂位置。日志只能追加，
没有提供修改或删除接口。

## 可选组件

主依赖只需 `anthropic` 和 `pypdf`，装完即可跑。两个重量级能力按需安装：

```bash
uv pip install -e ".[docling]"   # DOCX/PPTX/图片/表格/OCR
uv pip install -e ".[browser]"   # 浏览器自动填表
playwright install chromium      # browser 额外需要
```

`proofpath doctor` 会列出当前哪些可用。缺少 docling 时，遇到扫描件或 DOCX 会给出
明确的安装提示，而不是静默失败。

## 项目结构

```
src/proofpath/
  text.py        CJK 安全的归一化与分词（全角、零宽字符、中英混排）
  models.py      不可变领域类型
  parsers.py     文档 → 带页码的片段（pypdf / docling）
  retrieval.py   BM25 检索，零外部依赖
  reasoner.py    Claude 调用（结构化输出 + 提示缓存 + 拒答兜底）
  verifier.py    引用核验 —— 信任边界
  actions.py     风险分级与确认闸门
  audit.py       哈希链审计日志
  render.py      终端渲染
  cli.py         命令行入口
  demo.py        离线演示（含故意埋入的缺陷）
examples/policy.txt   示例政策（两页，含分页标记）
```

## 已知边界

- **不是最终资格认定**。系统给出的是「依据原文的初步判断」，输出中始终带有这句提示。
- **扫描件需要 OCR**。没装 docling 时，无文本层的 PDF 会直接报错并提示安装方式。
- **检索为词面匹配**。政策问答中用户用词通常与原文接近，因此 BM25 够用；
  但完全换一套说法（同义改写）可能检索不到，此时系统会拒答而非编造。
- **浏览器执行器尚未接入**。`plan` 目前只做风险分级演练；`browser-use` 已在
  可选依赖中固定版本，接线时不改动闸门逻辑。
